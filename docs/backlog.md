# 백로그 (v0.3)

기준 PRD: [screening-v0.3](prd/screening-v0.3.md) (이전 판 [v0.2](prd/screening-v0.2.md) · [v0.1](prd/screening-v0.1.md)). 우선순위: 필수 / 권장 / 선택.
- v0.2 대비(사용자 결정 2026-10-04): 기법 4개 확정·전부 필수(SEPA·소로스 보류 해제), "기술적 분석" 삭제, Gemini 2차 검수(승인/하향) → 근거 팩트체크 루프, workflow_dispatch 체크박스 실행 폼 기각 → 실행 요청 방법 결정(Q40).
- 보류 항목: 없음.

## 1단계 — MVP
| 우선순위 | 항목 |
|---|---|
| 필수 | 실행 요청 방법 결정(PRD Q40: 결과 웹페이지 실행 패널 / 이슈 양식 / Claude 대행 / Streamlit) — 결정 전에는 요청 경로 구현에 착수하지 않고, 실행 코어는 요청 방법과 무관하게 진행 |
| 필수 | 실행 요청 경로(Q40에서 정한 방식): 기법·범위 여러 개 선택 전달, 선택 목록은 레지스트리·범위 설정에서 생성, 소유자 요청만 실행, 요청 값 검증(PRD F1, AC1·AC10·AC22·AC29) |
| 필수 | 범위 프리셋(코스피200·S&P 100 등) + 여러 범위 동시 선택 + 기법별 기본(국장 전체·미장 전체)·허용 범위 + ETF 근사 + 범위 스냅샷 기록(PRD F15, AC21~AC24, Q37) |
| 필수 | 네이버 증권 어댑터(주식킹 방식, 국장·미장 1순위) + 대체 소스 순서(PRD F16, Q36) |
| 필수 | 플러그인 구조(strategies/<기법>/) + 공통 인터페이스 |
| 필수 | LLM 제공자 추상화 + Claude 판단: 판정 + 근거 주장 목록(숫자 주장은 도구 출력 연결, 정성·사실 주장은 출처 유형 표시)(PRD F4, Q32) |
| 필수 | 근거 팩트체크 루프: 숫자 주장 코드 대조 → Gemini 정성·사실 주장 팩트체크(확인/불일치/확인 불가 + 출처, Google Search 그라운딩) → 불일치 시 Claude 재판단(유지·하향만) → 주장·상태·출처·라운드 저장(PRD F13, AC18·AC25~AC28, Q42·Q43) |
| 필수 | LLM 도구 호출 구조: 데이터 조회·지표 계산·1차 필터를 도구로 제공, 숫자는 도구만 계산(PRD §2) |
| 필수 | 실행 1회 비용 상한(판단·재판단·팩트체크·그라운딩 포함, PRD F14) + 임시 $2 시험 실행으로 비용 실측 → 최종 상한 확정(Q31) |
| 필수 | LLM 출력 검증(후보 외·중복·적격 4개 이상·근거 없는 숫자 거부, 0~3건 허용, PRD F5) |
| 필수 | 결과 개수 규칙: 시장별 최대 3, 0건이면 "현재 적격 종목 없음" 기록, 조건 자동 완화 금지(PRD F3·F4) |
| 필수 | 기법 ① 마크 미너비니 SEPA — 착수 전 Q19~Q26, 분기 실적 소스(Q5). PRD §6.1 AC-S1~S5 |
| 필수 | 기법 ② 볼린저밴드 — 착수 전 Q41·Q44. 일봉 OHLCV만 필요. PRD §6.1 AC-B1~B3 |
| 필수 | 기법 ③ 워렌 버핏(해자) — 착수 전 Q5·Q17·Q18·Q30 |
| 필수 | 기법 ④ 조지 소로스(재귀성) — 착수 전 Q27~Q29·Q44, 분기 실적 소스(Q5) |
| 필수 | 결과 누적 저장 + 기준가(직전 종가) 기록 |
| 필수 | 사후 수익률 계산 + 기법별 통계(수·평균·중앙값·승률) |
| 필수 | 최소 결과/이력 화면 + "스크리닝 결과(통계용)" 표기 + 주장별 팩트체크 상태·출처·"확인 불가 근거 있음" 표시 |
| 필수 | 실패 격리(시장·기법 단위, 팩트체크 실패 포함) + 비밀값 처리(실행 요청 토큰 포함) |

- 기법 착수 순서(제안): 미결 질문 답이 나온 기법부터. 데이터 위험만 보면 볼린저(일봉만) → SEPA·소로스(분기 실적, Q5) → 버핏(다년 재무, Q5·Q17) 순으로 낮다.
