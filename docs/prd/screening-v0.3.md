- [architecture.md](../architecture.md)는 이 판에 맞춰 갱신됨(기법 4개 · 판단·팩트체크 §8.4 · 요청 JSON 하나로 실행 §10).

## 1. 목표
- 기법별로 국장(KOSPI/KOSDAQ)·미장에서 각각 **최대 3종목**을 스크리닝한다(적격 종목이 없으면 "현재 적격 종목 없음").
- 과거 모든 결과의 "추천 시점 직전 종가 → 현재" 수익률을 추적해 기법별 통계를 낸다.
- 모든 결과는 **"스크리닝 결과(통계용)"** 이며 투자 권유가 아니다.

## 2. 배경
- 사용자는 휴대폰으로 필요할 때만 실행을 요청하고 결과를 확인한다.
- 선정은 LLM이 도구 호출로 수행한다(데이터 조회·지표 계산·1차 필터·판정). 수천 종목을 한 번에 볼 수 없으므로 1차 필터 도구로 후보를 줄인다. 숫자는 도구(코드)만 계산하고 LLM은 숫자를 만들지 않는다.
- 판정의 정확성은 **Claude 판단 → 근거 팩트체크**(숫자 주장은 코드 대조, 정성·사실 주장은 Gemini)로 확보한다. 근거가 틀리면 판정은 유지되거나 내려갈 뿐 올라가지 않는다. 해자 원천(버핏)·재귀 경로(소로스)·촉매(SEPA) 같은 정성 근거가 주 대상이다.

### 3.2 기법별 설정
- 판정 등급: 적격 / 관찰 / 제외(볼린저·버핏·소로스). SEPA 원문은 BUY CANDIDATE / WATCH / EXCLUDE(표기 Q24, WATCH 추적 Q23). 개수 규칙(최대 3)은 최상위 등급에만 적용하고 아래 등급으로 채우지 않는다.
- 유동성 하한(무거운 데이터 조회 전 적용): SEPA 국장 = 시가총액 ≥ 1조원·20일 평균 거래대금 ≥ 100억원(사용자 설정, 다른 기법에 미적용, 미장 Q19) · 버핏 = 시가총액(미장 $10억 제안, 국장 Q30) · 볼린저·소로스 = Q44.

## 4. 사용자 시나리오
1. 사용자가 휴대폰에서 실행을 요청한다(방법 Q40). 기법을 하나 이상 고르고, 필요하면 범위를 하나 이상 고른다(예: 코스피200 + 코스닥150, S&P 100). 안 고르면 국장 전체·미장 전체를 쓴다.
2. 실행: 데이터 수집 → 기법×시장별 1차 필터(도구) → Claude 판단(판정 + 근거 주장 목록) → 숫자 주장 코드 대조 → Gemini가 정성·사실 주장 팩트체크(출처 포함) → 불일치가 있으면 Claude 재판단(유지·하향만) → 저장.
3. 결과 화면에서 기법별 국장·미장 최대 3종목(없으면 "현재 적격 종목 없음"), 사유, 주장별 팩트체크 상태·출처를 본다.
4. 이력 화면에서 과거 모든 결과의 현재까지 수익률과 기법별 통계를 본다.

## 5. 기능 요구사항
| ID | 요구사항 |
|---|---|
| F1 | 수동 실행(요청 시에만): 예약·push 자동 실행 없이 사용자 요청이 있을 때만 실행한다. **요청 방법은 Q40.** 요청은 기법(여러 개), 범위(여러 개, 시장별 미선택 시 기본 범위), 시장, 모드(스크리닝 / 수익률만 갱신), dry-run(모킹·비용 0)을 실행에 전달한다. 선택 가능한 기법·범위 목록은 레지스트리·범위 설정에서 만들어지며, 새 기법은 공통 코드 수정 없이 선택할 수 있게 된다. 실행은 저장소 소유자의 요청으로만 시작하고, 요청 값은 실행 전에 검증한다(등록된 ID만). |
| F2 | 플러그인: 각 기법은 독립 모듈이며, 공통 인터페이스(1차 필터 → LLM 판단 입력 생성 → 결과)를 따른다. 기법 추가 시 공통 코드 수정 없이 등록만으로 동작한다. |
| F3 | 1차 필터: 기법별 숫자 조건으로 시장별 후보군을 N개 이하로 줄인다(N은 Q4). 통과 종목이 적어도 조건을 자동 완화하지 않으며, 0개면 LLM을 호출하지 않고 "현재 적격 종목 없음"으로 기록한다. |
| F4 | 판단(Claude): 도구가 반환한 후보군 데이터로 시장별 **최대 3종목**(0~3)을 적격으로 판정하고(그 외 관찰·제외) 종목별 사유를 낸다. 판정마다 **근거 주장 목록**을 구조화해 제출한다 — ① 숫자 주장: 특정 도구 출력(호출 ID·필드)에 연결 ② 정성·사실 주장: 예 "특허로 보호", "최근 분기 매출 증가 원인은 ○○", 출처 유형(도구 자료 / 모델 지식) 표시. 기준 미달 종목으로 개수를 채우지 않는다. 제공자는 설정으로 교체 가능하다. |
| F5 | 출력 검증: 후보군 밖 종목, 중복, 적격 4개 이상, 사유·숫자 주장에 도구 반환값에 없거나 연결된 출력과 다른 숫자가 있으면 거부하고 재제출 또는 실패 처리한다. 0~3건 응답은 정상이다. |
| F6 | 결과 저장: 실행 ID, 실행 시각, 기법, 시장, 종목코드/명, 기준가(추천 시점 직전 종가)와 그 날짜, 사유, 판단·팩트체크 제공자/모델명, 1차 필터 통과 종목 수, 근거 주장·팩트체크 기록(F13)을 저장한다. 0건인 기법·시장도 "현재 적격 종목 없음"과 통과 종목 수를 실행 이력에 남긴다. 과거 결과는 덮어쓰지 않고 누적한다. |
| F7 | 수익률 추적: 모든 과거 결과에 대해 (현재가 또는 최신 종가 ÷ 기준가 − 1)을 계산해 표시한다. 현재가 산출 시점을 함께 표시한다. (SEPA의 Entry 기준·WATCH 추적 여부는 Q22·Q23) |
| F8 | 기법별 통계: 기법·시장별 결과 수, 평균 수익률, 중앙값, 플러스 수익 비율(승률)을 표시한다. 0건 실행은 수익률 계산 대상이 아니다. |
| F9 | 표기: 결과/이력 화면 상단에 "스크리닝 결과(통계용) — 투자 권유 아님"을 표시한다. 매수/매도 등 권유 표현을 쓰지 않는다(SEPA 판정 원문 표기와의 충돌은 Q24). |
| F10 | 보안: API 키, 실행 요청용 토큰(Q40) 등 비밀값은 GitHub Secrets/환경변수 또는 사용자 기기에만 두고, 저장소·결과 사이트·로그에 넣지 않는다. |
| F11 | 실패 처리: 데이터 소스 오류(예: 429), LLM 오류(판단·팩트체크) 시 해당 기법·시장을 "실패"로 기록하고 다른 기법·시장은 계속 진행한다. 잘못된 결과를 저장하지 않는다. "현재 적격 종목 없음"은 실패가 아니다. |
| F12 | 기법 전용 판정: 기법 명세가 판정 등급·단계별 기록·코드 검증 규칙을 정의하면(SEPA·볼린저) 기법 전용 필드로 저장하고, 코드 검증을 통과하지 못한 종목은 최상위 등급(SEPA: BUY CANDIDATE)으로 저장하지 않는다. |
| F13 | 근거 팩트체크·재판단: ① 같은 데이터 스냅샷에서 Claude가 판정과 근거 주장 목록을 낸다(F4). ② 숫자 주장은 코드가 연결된 도구 출력과 대조한다(F5). ③ 적격·관찰 판정의 정성·사실 주장은 Gemini가 종목·주장 목록과 같은 스냅샷 자료를 받아 주장마다 **확인 / 불일치 / 확인 불가**와 출처(URL·제목)를 낸다. Google Search 그라운딩을 쓸 수 있으며 응답의 출처 메타데이터(groundingMetadata의 groundingChunks·groundingSupports — [Gemini API 문서](https://ai.google.dev/gemini-api/docs/google-search), 검색 결과 요약으로 확인)를 저장한다. Gemini는 판정을 내거나 바꾸지 않고 종목을 더하지 않으며, 메모는 판정·통계 계산에 쓰지 않는다. 정성 주장이 없는 종목은 팩트체크 요청에 넣지 않는다. ④ 불일치가 하나라도 있으면 Claude가 그 주장을 뺀 채 그 종목을 재판단한다. 판정은 유지 또는 하향만 가능하고(상향 금지), 적격은 불일치 주장에 기댄 채 남을 수 없다. 재판단에서 새로 낸 주장은 다시 팩트체크한다(최대 횟수·한도 소진 처리 Q43). ⑤ 확인 불가 처리는 Q42(제안: 확인 불가만 있으면 판정 유지 + "확인 불가 근거 있음" 표시). ⑥ 주장(유형·내용·연결 출력·출처 유형)·주장별 상태·출처·조회 시각·라운드별 판정·최종 판정을 저장하고, 불일치율과 재판단으로 바뀐 판정 수를 집계한다. ⑦ 판단 또는 팩트체크가 실패(오류·한도)하면 그 기법·시장은 "실패(사유)"로 기록하고 최종 적격을 내지 않는다(Claude 판정은 기록). ⑧ 판단·팩트체크 제공자는 설정으로 바꿀 수 있다. |
| F14 | 비용 상한: 실행 1회 LLM 비용(Claude 판단·재판단, Gemini 팩트체크, 검색 그라운딩 과금 — 과금 방식 미확인)을 추적하고 상한(Q31, 첫 시험 실행 임시 $2)에 닿으면 새 호출을 멈춘다. 못 돌린 기법·시장은 "예산 초과로 미실행"으로 기록하고, 부분 결과를 완성 결과처럼 보이지 않게 한다. 실행마다 모델별·기법별 비용을 기록한다. |
| F15 | 범위(유니버스) 제한: 범위 프리셋을 둔다 — 국장: 전체·코스피 전체·코스닥 전체·코스피200·코스피100·코스피50·코스닥150·KRX300 / 미장: 전체·나스닥 전체·NYSE 전체·S&P 500·S&P 100·나스닥100·다우30·필라델피아 반도체·러셀2000. 거래소 전체 범위는 보통주만 쓰고, 무거운 데이터는 기법의 유동성 하한(§3.2)으로 먼저 줄인 뒤 조회한다. 기법마다 시장별 **기본 범위 목록**과 허용 범위를 설정한다. 실행 요청에서 범위를 여러 개 고르면 고른 기법 모두에 적용하고(허용 범위 밖은 그 기법에서 제외·기록, 남는 범위가 없으면 그 기법×시장은 "실패(범위)"), 시장별로 하나도 안 고르면 기본 범위(국장 전체·미장 전체)를 쓴다. 여러 범위는 합집합(중복 1번)에서 시장별 최대 3종목을 고른다(제안, Q37). 공식 구성종목을 못 받으면 ETF 보유 종목으로 근사하고 "근사"로 표시한다. 실행마다 범위별 ID·출처·근사 여부·기준일·종목 수를 기록하고, 결과 행에 범위 집합과 그 종목이 속한 범위를 저장한다. |
| F16 | 데이터 소스: 주식킹(stock-DASHBB)과 같은 네이버 증권 API를 국장·미장 1순위 소스로 쓰고(같은 요청 헤더·재시도·장 마감 확인), 실패 시 설정된 대체 소스(pykrx·DART·yfinance)로 넘어간다. 어느 소스 값인지 기록한다. 비공식 API이므로 응답 형식이 바뀌면 그 소스를 "실패"로 처리하고 빈 결과로 바꾸지 않는다. |
| F17 | **종목 상세 화면** — 가정(사용자 확인 전, Q45): '실적' = 선정 후 성과 + 기업 실적 둘 다. 결과·이력 화면의 각 종목에서 연다. ① **선정 후 성과**(결과 레코드별 — 여러 건이면 이력에서 고른 건, 기본은 가장 최근 선정, Q45 제안): 기준일 이후 일별 종가 차트와 기준가 기준선, 현재 수익률(F7), 경과 거래일 수, 기간 중 최고 수익률과 그 날짜, 고점 대비 최대 하락폭, 같은 기간 비교 지수(Q46) 수익률과 초과 수익(종목 수익률 − 지수 수익률, %p). 계산 규칙은 Q49, 가격 조정 기준은 Q14. ② **기업 실적**: 분기·연간 전환. 매출액·영업이익·순이익·EPS·영업이익률(영업이익 ÷ 매출액), 최근 분기의 전년 동기 대비 증감, 최근 4개 분기 추이. 값마다 기간·발표일·기준(연결/별도)·출처를 표시하고, 공시 원값이 아닌 산출값(예: 4분기 = 연간 − 3분기 누적)은 "산출"로 표시한다. 소스·기준·갱신 시점은 Q47. ③ **판단 근거**: 그 레코드의 F13 저장값(주장·주장별 팩트체크 상태·출처)을 연결해 보여 준다(새로 만들지 않음). ④ **선정 이력**: 같은 종목이 여러 기법·여러 실행에서 선정되면 레코드마다 한 줄(기법·선정일(실행일)·판정·기준가와 기준일·수익률)로 따로 보여 준다(Q13 연계). ⑤ 숫자는 모두 코드가 조회·계산하고 LLM은 쓰지 않는다(LLM 비용 0). 결과 사이트는 정적(GitHub Pages, [architecture §10](../architecture.md))이므로 성과·실적 데이터는 워크플로 실행(스크리닝·수익률만 갱신, F1) 때 계산해 JSON으로 저장하고, 화면은 그 파일만 읽으며 데이터 기준일(최신 종가일·실적 조회 시각)을 표시한다. ⑥ 값이 없으면 "미확인(사유)"로 표시하고 0·다른 기간 값·추정값으로 채우지 않는다. 상장폐지·데이터 없음 표시는 Q48. ⑦ 상단에 "스크리닝 결과(통계용) — 투자 권유 아님"을 두고 권유 표현을 쓰지 않는다(F9). 실적 항목은 고정 라벨로 표시한다(원 계정명에 금지어가 들어갈 수 있음, 예: 매도가능금융자산 — Q9). |

## 6. 합격 기준 (tester 검증용)
v0.2 번호 유지 — 문구 수정: AC1·AC2·AC3·AC5·AC9~AC12·AC15·AC18·AC20·AC22·AC23 / 신규: AC25~AC29, AC-B1~AC-B3.
- AC1: 스크리닝 워크플로 파일에 `schedule`·`push` 트리거가 없고, Q40에서 정한 요청 경로로만 실행이 시작된다. 저장소 소유자가 아닌 계정의 요청을 모킹하면 실행이 시작되지 않는다.
- AC2: 모든 기법·시장을 선택해 1회 실행하면, 성공한 기법·시장마다 0~3건의 결과 레코드가 생성되고, 0건이면 그 기법·시장의 실행 이력에 "현재 적격 종목 없음"이 기록된다.
- AC3: 모든 결과 레코드에 F6 필드가 비어 있지 않다(사유 포함, 근거 주장 1개 이상).
- AC4: 기준가는 실행 시각 이전 마지막 거래일의 종가이며, 해당 날짜가 레코드에 저장된다. (예: 장중 실행 시 전 거래일 종가, 휴장일 실행 시 직전 거래일 종가)
- AC5: LLM이 후보군 밖 종목·중복·적격 4개 이상을 반환하도록 모킹하면, 해당 응답은 저장되지 않고 재시도/실패로 기록된다.
- AC6: 동일 기법을 2회 실행하면 이력에 두 실행이 모두 남는다(첫 실행 결과가 덮어써지지 않음).
- AC7: 기준가 10,000원·현재가 11,000원인 레코드의 수익률이 +10.00%로 표시된다.
- AC8: 기법별 통계(결과 수·평균·중앙값·승률)가 저장된 레코드로 수동 계산한 값과 일치한다.
- AC9: 결과/이력 화면에 "스크리닝 결과(통계용)" 문구가 있고, 화면·저장 데이터에 "매수", "매도", "추천 매수" 등 권유 표현이 없다(LLM 사유·팩트체크 메모 포함 — 검출 시 처리와 외부 출처 제목 처리는 Q9, SEPA 판정 표기는 Q24).
- AC10: 새 더미 기법 폴더(`strategies/<id>/`)를 추가하면 공통 코드 수정 없이 실행 요청의 선택 가능한 기법 목록에 나타나고, 그 기법만 선택해 실행하면 결과에 나타난다. 선택 목록이 생성 파일인 방식(예: 이슈 양식)이면 레지스트리와 어긋날 때 CI가 실패한다.
- AC11: 판단·팩트체크 제공자 설정값만 바꿔(코드 수정 없이) 실행 모델 구성이 바뀐다(Claude·Gemini 모킹 제공자로 검증, CI에서 유료 호출 없음).
- AC12: 저장소 전체에서 API 키·계좌번호·토큰 패턴이 검출되지 않는다(시크릿 스캔 통과).
- AC13: 한 시장 데이터 소스를 실패하도록 모킹하면, 그 시장은 "실패"로 기록되고 나머지 시장/기법 결과는 정상 저장된다.
- AC14: 휴대폰 폭(360px)에서 결과·이력 화면이 가로 스크롤 없이 읽힌다.
- AC15: LLM이 후보 중 2종목만 적격으로 반환하도록 모킹하면 2건이 정상 저장되고, 그 기법·시장은 "실패"로 기록되지 않는다.
- AC16: 1차 필터 통과 종목이 0개인 입력으로 실행하면 LLM이 호출되지 않고, 결과·이력 화면에 그 기법·시장이 "현재 적격 종목 없음"으로 표시된다.
- AC17: 1차 필터 통과 종목이 1개인 입력으로 실행하면 결과는 1건 이하이고, 1차 필터 임계값은 설정값 그대로다(자동 완화 없음).
- AC18: 모킹 Claude가 A·B·C를 적격으로 내고(각각 정성 주장 포함), 모킹 Gemini가 A의 주장은 모두 확인, B의 "특허로 보호"는 불일치(출처 1개), C의 정성 주장은 모두 확인 불가로 내면: Claude가 B를 그 주장 없이 재판단해(모킹: 관찰) 최종은 A 적격 · B 관찰 · C 적격 + "확인 불가 근거 있음" 표시로 저장된다(C는 Q42 제안 규칙 기준). 주장 목록·주장별 상태·출처·라운드별 판정·라운드 수가 저장된다. 재판단 응답이 불일치 주장을 다시 근거로 쓰거나 판정을 올리면 거부되고(불일치 주장 없이 적격을 유지하는 응답은 허용), Gemini 응답에 판정 변경이나 새 종목이 있으면 거부된다.
- AC19: 모킹 비용 상한을 첫 기법 실행 비용보다 작게 두면, 이후 기법·시장은 "예산 초과로 미실행"으로 기록되고 실행 비용 기록이 남는다.
- AC20: 사유나 숫자 주장에 도구 반환값에 없는 숫자, 또는 연결된 도구 출력과 다른 숫자가 들어가도록 모킹하면 그 응답은 저장되지 않고 재제출/실패로 기록된다.
- AC21: 기법의 국장 범위를 코스피200(픽스처 구성종목)으로 두고 실행하면 모든 후보·결과가 그 구성종목 안에 있고, 결과 행에 범위 ID가, 실행 기록에 범위 출처·종목 수가 저장된다.
- AC22: 기법 2개 중 1개만 선택한 실행 요청은 그 기법만 실행한다. 선택한 범위는 선택한 기법 모두에 전달되고, 기법의 허용 범위 밖 범위는 그 기법에서 빠지며, 남는 범위가 없으면 그 기법만 "실패(범위)"로 기록된다. 실행 기록에 전달받은 기법·범위 목록이 저장된다.
- AC23: 범위 2개(픽스처 코스피200 10종목 + 코스닥150 8종목, 겹침 2종목)를 선택해 실행하면 후보는 합집합 16종목 안에서만 나오고(중복 1번), 결과는 시장별 최대 3건이며, 결과 행에 범위 집합(`kospi200+kosdaq150`)과 그 종목이 속한 범위가 저장된다.
- AC24: 범위의 공식 구성종목 소스가 실패하도록 모킹하면 ETF 보유 종목(주식만)으로 대체되고, 실행 기록과 결과 화면에 "근사"가 표시된다.
- AC25: 모킹 Gemini 팩트체크가 오류(또는 호출 한도 초과)를 내면 그 기법·시장은 "실패(팩트체크)"로 기록되고 최종 적격은 저장되지 않으며 Claude 판정은 실행 기록에 남는다. 다른 기법·시장은 정상 진행된다.
- AC26: 근거 주장이 모두 숫자 주장인 종목은 Gemini 팩트체크 요청에 포함되지 않고(기법·시장의 모든 종목이 그렇다면 Gemini 호출 0), 숫자 대조를 통과하면 Claude 판정이 최종 판정으로 저장된다.
- AC27: Gemini가 출처 없이 "확인" 또는 "불일치"를 내도록 모킹하면 그 주장은 "확인 불가"로 저장된다(Q42 제안 규칙 기준).
- AC28: 재판단에서 낸 새 주장도 계속 불일치로 나오도록 모킹하면 재판단은 Q43 상한(제안 2회)에서 멈추고 Q43 처리 규칙(제안: 불일치 주장에 기댄 판정은 한 단계 낮춤)으로 확정된다. 어느 라운드에서도 판정이 이전보다 올라가지 않는다.
- AC29: 실행 요청에 등록되지 않은 기법·범위 ID나 허용되지 않은 문자가 있으면 데이터 수집·LLM 호출 없이 거부되고, 사유와 유효 ID 목록이 기록된다.

### 6.1 기법별 합격 기준 (해당 질문 결정 후 기대값 확정)
SEPA는 Q19~Q26, 볼린저는 Q41 결정 후 검증한다. 결정이 제안과 다르면 기대값도 바꾼다.
- AC-S1: 국장에서 시가총액 4,000억원 종목, 또는 시가총액 2조원·20일 평균 거래대금 90억원 종목은 SEPA 1차 필터를 통과하지 못한다.
- AC-S2: Pivot 10,000 · 기준일 종가 10,600이면 Extension이 +6.00%로 계산된다.
- AC-S3: Entry 10,000 · Stop 9,500 · Target 10,900이면 R/R 1.80으로 계산되고 BUY CANDIDATE로 저장되지 않는다. Target 11,000이면 R/R 2.00으로 R/R 조건을 충족한다.
- AC-S4: LLM이 구조 레벨 목록에 없는 Stop을 반환하거나, 마지막 일봉 날짜가 기준일보다 이르면 그 종목은 BUY CANDIDATE로 저장되지 않는다.
- AC-S5: BUY CANDIDATE 조건을 충족하는 종목이 1개뿐인 모킹 입력이면 BUY CANDIDATE는 1건만 저장되고, 다른 종목의 WATCH 판정은 바뀌지 않는다.
- AC-B1: 20일 종가가 9,900·10,100 교대(마지막 날 10,100)인 픽스처에서 중간 밴드 10,000, 상단 10,200, 하단 9,800, %b 0.75, BandWidth 0.0400으로 계산된다(모집단 표준편차 기준 — Q41).
- AC-B2: 기준일 종가가 상단 밴드 위(%b > 1)여도 Squeeze 조건(설정값)을 충족하지 않은 픽스처 종목은 볼린저 1차 필터를 통과하지 못한다(밴드 태그·돌파만으로는 신호가 아님).
- AC-B3: Squeeze·상단 돌파를 충족한 픽스처 종목의 기준일 값을 %b 0.85·MFI(10) 78로 두면 1차 필터를 통과하지 못하고, MFI(10) 82로 두면 통과한다(Method II 확인, 제안 기준 %b > 0.8·MFI(10) > 80).

### 6.2 종목 상세 화면 합격 기준 (F17)
Q45 가정과 Q46~Q49 제안 기준이다. 결정이 다르면 기대값도 바꾼다. 모두 픽스처·모킹 데이터로 검증한다(네트워크·유료 LLM 호출 없음). 표시 자릿수는 AC7과 같다.
- AC30: 기준가 10,000(기준일 D0), 이후 종가 D1 10,500 · D2 11,000 · D3 9,900 · D4 10,450, 비교 지수 종가 D0 2,500.00 · D4 2,550.00인 레코드의 상세 화면에 현재 수익률 +4.50%, 경과 거래일 4, 최고 수익률 +10.00%(D2), 고점 대비 최대 하락폭 −10.00%, 지수 수익률 +2.00%, 초과 수익 +2.50%p가 표시되고, D1~D4 종가 차트에 기준가 10,000 기준선이 함께 그려진다.
- AC31: 기준가 10,000, 이후 종가 D1 9,500 · D2 9,800이면 최고 수익률 −2.00%(D2), 최대 하락폭 −5.00%(기준가를 첫 고점으로 포함)로 표시된다. 기준일 이후 종가가 아직 없는 레코드는 경과 거래일 0, 현재 수익률 0.00%, 최고 수익률·최대 하락폭 "해당 없음"으로 표시된다(Q49 제안).
- AC32: 모킹 DART 응답(연결, 단위 억원)이 매출 2025년 1분기 200 · 2분기 240 · 3분기 260(3분기 누적 700) · 2025년 연간 1,000 · 2026년 1분기 250, 영업이익 2025년 1분기 20 · 2026년 1분기 30이면, 분기 화면에 최근 4개 분기 매출 240 · 260 · 300 · 250이 표시되고 2025년 4분기 300에는 "산출"이 붙는다. 최근 분기(2026년 1분기)의 전년 동기 대비 매출 +25.00% · 영업이익 +50.00%, 영업이익률 12.00%가 표시되고, 2025년 4분기 EPS는 "미확인"이다. 같은 값으로 만든 모킹 SEC companyfacts(10-K 연간, 3분기 10-Q 9개월 누적)도 같은 결과를 낸다(Q47 제안).
- AC33: 연간으로 바꾸면 2025년 매출 1,000과 2024년(픽스처 800) 대비 +25.00%가 표시된다. 모든 실적 값에 기간·발표일(픽스처 접수일)·기준(연결/별도)·출처(DART 또는 SEC EDGAR)가 함께 보인다. 연결 재무제표 조회가 "013 조회된 데이타가 없습니다"로 모킹된 종목은 별도 재무제표 값이 "별도" 표시와 함께 나온다(Q47 제안).
- AC34: 종목 X가 SEPA 1회(기준가 10,000)·볼린저 2회(기준가 11,000 · 12,000) 선정되고 최신 종가가 13,200인 픽스처에서, X 상세 화면의 선정 이력에 3줄(기법·선정일·판정·기준가와 기준일·수익률)이 따로 표시되고 수익률은 각각 +32.00% · +20.00% · +10.00%다. 각 줄에서 그 레코드의 주장 목록·주장별 팩트체크 상태·출처를 볼 수 있고, 내용은 저장된 F13 기록과 같다.
- AC35: 재무 소스 실패(또는 데이터 없음)를 모킹하면 기업 실적은 "미확인(사유)"로 표시되고 0이나 다른 분기 값으로 채워지지 않으며, 선정 후 성과는 정상 표시된다. 비교 지수만 실패하면 지수 수익률·초과 수익만 "미확인"이다. 상장폐지 이벤트(마지막 거래일 D, 마지막 종가 8,000, 기준가 10,000)가 있는 종목은 상세 화면·이력에서 빠지지 않고 "상장폐지(D)"와 수익률 −20.00%로 표시되며, 다음 갱신 실행 뒤에도 값이 같다. 종가 조회만 실패한 종목은 직전 저장 수익률이 그 기준일·"이번 갱신 실패" 표시와 함께 남는다(Q48 제안).
- AC36: 수익률만 갱신 모드의 모킹 실행은 LLM 호출 0·LLM 비용 $0으로 기록되고, 스크리닝 모드에서도 상세 데이터 생성 단계에서는 LLM 제공자가 호출되지 않는다(모킹 제공자 호출 기록으로 확인). 두 모드 모두 상세 화면용 JSON을 저장하며, 수익률만 갱신 실행 뒤 최신 종가·성과 지표는 새 픽스처 값으로 바뀌고 기존 레코드의 기준가·기준일은 바뀌지 않는다. 네트워크를 차단한 채 생성된 사이트 파일만으로 상세 화면이 열리고(화면이 외부 API를 호출하지 않음) 데이터 기준일이 보인다. 상세 화면에도 "스크리닝 결과(통계용) — 투자 권유 아님"이 있고 권유 표현이 없으며(AC9 기준), 360px 폭에서 가로 스크롤 없이 읽힌다(AC14 기준).
