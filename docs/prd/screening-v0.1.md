# PRD v0.1 — 기법별 종목 스크리닝 + 사후 수익률 추적

- 상태: 초안(v0.1) · 작성: product-manager · 작성일: 2026-10-03
- 관련 문서: [기술적 분석](../strategies/technical.md) · [워렌 버핏(해자)](../strategies/buffett-moat.md) · [백로그](../backlog.md)

## 1. 목표
- 기법(전략)별로 국장(KOSPI/KOSDAQ) 3종목 + 미장 3종목을 스크리닝한다.
- 과거 모든 스크리닝 결과의 "추천 시점 직전 종가 → 현재" 수익률을 추적해 기법별 통계를 낸다.
- 모든 결과는 **"스크리닝 결과(통계용)"** 이며 투자 권유가 아니다.

## 2. 배경
- 사용자는 휴대폰 브라우저/GitHub 앱으로 필요할 때만 실행하고 결과를 확인하고자 한다.
- 최종 3종목 선정은 사용자 결정에 따라 **전부 LLM이 판단**한다. LLM은 수천 종목을 한 번에 볼 수 없으므로, 기법마다 **숫자 기반 1차 필터**로 후보를 줄인 뒤 LLM이 3종목과 사유를 고른다.

## 3. 범위
### 포함
- 기법 ① 기술적 분석 ② 워렌 버핏(경제적 해자 중심)
- 플러그인 구조: 기법을 `strategies/<기법>/` 단위로 추가 가능
- GitHub Actions 수동 실행(workflow_dispatch, "Run workflow" 버튼)
- 결과 저장(이력 누적) 및 최소한의 결과/통계 화면
- 사후 수익률 추적 및 기법별 통계
- LLM 제공자 교체 가능 구조(제공자 자체는 미결)

### 제외
- 조지 소로스, 마크 미너비니 SEPA (보류 — 사용자 지시 전 착수 금지)
- 매수/매도 권유, 자동 주문, 알림
- 예약(cron) 자동 실행
- 실시간 시세(있으면 좋음 수준 — 백로그 '선택')
- 시각 디자인

## 4. 사용자 시나리오
1. 사용자가 GitHub(웹/앱)에서 워크플로를 열고 "Run workflow"를 누른다. 입력값으로 기법(전체/개별)을 고른다.
2. 워크플로가 데이터 수집 → 기법별 1차 필터 → LLM 판단 → 결과 저장을 수행한다.
3. 사용자는 휴대폰 브라우저로 결과 화면을 열어, 기법별 국장 3 / 미장 3 종목과 LLM 사유를 본다.
4. 사용자는 이력 화면에서 과거 모든 스크리닝 결과의 현재까지 수익률과 기법별 통계를 본다.

## 5. 기능 요구사항
| ID | 요구사항 |
|---|---|
| F1 | 수동 실행: workflow_dispatch로만 실행되며, 기법 선택 입력(전체 또는 기법 ID)을 받는다. |
| F2 | 플러그인: 각 기법은 독립 모듈이며, 공통 인터페이스(1차 필터 → LLM 판단 입력 생성 → 결과)를 따른다. 기법 추가 시 공통 코드 수정 없이 등록만으로 동작한다. |
| F3 | 1차 필터: 기법별 숫자 조건으로 시장별 후보군을 N개 이하로 줄인다(N은 미결 Q4). |
| F4 | LLM 판단: 후보군 데이터를 LLM에 전달해 시장별 정확히 3종목과 종목별 사유를 받는다. 제공자는 설정으로 교체 가능하다. |
| F5 | LLM 출력 검증: 후보군 밖 종목, 중복, 3개 미만/초과 응답은 거부하고 재시도 또는 실패 처리한다. |
| F6 | 결과 저장: 실행 ID, 실행 시각, 기법, 시장, 종목코드/명, 기준가(추천 시점 직전 종가)와 그 날짜, 사유, LLM 제공자/모델명, 1차 필터 통과 종목 수를 저장한다. 과거 결과는 덮어쓰지 않고 누적한다. |
| F7 | 수익률 추적: 모든 과거 결과에 대해 (현재가 또는 최신 종가 ÷ 기준가 − 1)을 계산해 표시한다. 현재가 산출 시점을 함께 표시한다. |
| F8 | 기법별 통계: 기법·시장별 결과 수, 평균 수익률, 중앙값, 플러스 수익 비율(승률)을 표시한다. |
| F9 | 표기: 결과/이력 화면 상단에 "스크리닝 결과(통계용) — 투자 권유 아님"을 표시한다. 매수/매도 등 권유 표현을 쓰지 않는다. |
| F10 | 보안: API 키 등 비밀값은 GitHub Secrets/환경변수로만 읽는다. 저장소에 커밋하지 않는다. |
| F11 | 실패 처리: 데이터 소스 오류(예: 429), LLM 오류 시 해당 기법·시장을 "실패"로 기록하고 다른 기법·시장은 계속 진행한다. 잘못된 결과를 저장하지 않는다. |

## 6. 합격 기준 (tester 검증용)
- AC1: 워크플로 파일에 트리거가 `workflow_dispatch`만 있다(`schedule`, `push` 트리거 없음).
- AC2: "전체"로 1회 실행하면, 성공한 기법마다 KR 3건 + US 3건, 총 6건의 결과 레코드가 생성된다.
- AC3: 모든 결과 레코드에 F6 필드가 비어 있지 않다(사유 포함).
- AC4: 기준가는 실행 시각 이전 마지막 거래일의 종가이며, 해당 날짜가 레코드에 저장된다. (예: 장중 실행 시 전 거래일 종가, 휴장일 실행 시 직전 거래일 종가)
- AC5: LLM이 후보군 밖 종목·중복·3개가 아닌 응답을 반환하도록 모킹하면, 해당 응답은 저장되지 않고 재시도/실패로 기록된다.
- AC6: 동일 기법을 2회 실행하면 이력에 두 실행이 모두 남는다(첫 실행 결과가 덮어써지지 않음).
- AC7: 기준가 10,000원·현재가 11,000원인 레코드의 수익률이 +10.00%로 표시된다.
- AC8: 기법별 통계(결과 수·평균·중앙값·승률)가 저장된 레코드로 수동 계산한 값과 일치한다.
- AC9: 결과/이력 화면에 "스크리닝 결과(통계용)" 문구가 있고, 화면·저장 데이터에 "매수", "매도", "추천 매수" 등 권유 표현이 없다(LLM 사유 포함 — 프롬프트로 금지하고 검출 시 처리, 처리 방식은 미결 Q9).
- AC10: 새 더미 기법을 플러그인 디렉터리에 추가하고 등록만 하면, 공통 코드 수정 없이 워크플로 선택지와 결과에 나타난다.
- AC11: LLM 제공자 설정값만 바꿔(코드 수정 없이) 다른 제공자 구현으로 실행된다(최소 1개 제공자 + 모킹 제공자로 검증).
- AC12: 저장소 전체에서 API 키·계좌번호 패턴이 검출되지 않는다(시크릿 스캔 통과).
- AC13: 한 시장 데이터 소스를 실패하도록 모킹하면, 그 시장은 "실패"로 기록되고 나머지 시장/기법 결과는 정상 저장된다.
- AC14: 휴대폰 폭(360px)에서 결과·이력 화면이 가로 스크롤 없이 읽힌다.

## 7. 성공 지표
- 수동 실행 1회 성공률(전 기법·전 시장 결과 생성) ≥ 90% (최근 10회 기준)
- 실행 1회 소요 시간: 미결 Q10 (GitHub Actions 작업 최대 시간 내)
- 누적 결과로 기법별 통계가 화면에 표시됨
