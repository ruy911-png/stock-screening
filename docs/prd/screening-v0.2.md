## 0. v0.1 대비 변경
- **결과 개수 규칙(모든 기법 공통)**: 시장별 "정확히 3" → **최대 3(0~3)**. 기준을 충족하는 종목만 선정하고, 0이면 "현재 적격 종목 없음"으로 기록한다. 조건 완화·기준 미달 종목으로 채우기 금지(v0.1 Q15 해결). 기법 명세의 "정확히 3종목" 표현은 이 규칙으로 대체된다.
- **SEPA**: 명세 작성 완료, 구현은 보류 유지. 판정 등급 3단계와 SEPA 전용 국장 유니버스 기준 반영(§3.2, F12).
- **버핏·소로스 명세**: 메인이 웹 조사 기반으로 재작성 완료(v0.2). 소로스는 보류 유지.
- **LLM 구조(사용자 결정)**: LLM이 도구 호출로 전 과정(데이터 조회·지표 계산·1차 필터·판정)을 수행한다. 숫자는 도구(코드)만 계산한다. "전 과정 = 도구 호출"은 메인의 해석이며 사용자 이의 없음.
- **순차 검수(사용자 결정, 2026-10-04 변경)**: Claude가 1차 검수(판정)하고 Gemini가 같은 데이터로 2차 검수(승인 또는 하향)한다. 둘 다 적격일 때만 적격, 하향된 종목은 재검토 후에도 이견이면 낮은 쪽. Gemini는 새 종목을 더하지 않는다(Q39). 이전의 "두 모델 각자 판정 후 합의" 방식을 대체한다(Q1 해결).
- **비용 상한(사용자 결정)**: 실행 1회 상한을 둔다. 첫 시험 실행은 임시 $2로 실제 비용을 측정한 뒤 사용자가 최종 상한을 정한다(Q3 → Q31로 대체).
- **기법 선택·범위(사용자 결정)**: 실행 폼에서 기법별 체크박스로 고르고, 범위(코스피200·S&P 100 등)를 **여러 개** 체크할 수 있다. 안 고르면 기법별 기본 범위를 쓴다(F1·F15). 여러 범위를 합치는 방식은 Q37.
- **기본 범위(사용자 결정, 2026-10-04)**: 범위를 안 고르면 국장 전체(코스피+코스닥)·미장 전체(NYSE·나스닥 등 상장 보통주)를 쓴다. 기법 공통(Q34 해결). 종목 수가 많아 무거운 데이터는 유동성 하한으로 먼저 줄인 뒤 받는다.
- **범위 근사(사용자 결정)**: 공식 지수 구성종목을 못 받으면 지수 추종 ETF 보유 종목으로 대신하고 "근사"로 표시한다(Q35 해결).
- **데이터 소스(사용자 결정)**: 주식킹과 같은 네이버 증권 API(비공식)를 국장·미장 1순위 소스로 쓴다(F16).
- **미결 질문**: 번호 유지(해결된 Q1·Q3·Q15·Q34·Q35 삭제, Q11 해결), 신규 Q19~Q26(SEPA), Q27~Q33(소로스·버핏·멀티모델), Q36·Q37·Q38(범위·데이터 소스), Q39(2차 검수).

## 1. 목표
- 기법(전략)별로 국장(KOSPI/KOSDAQ)과 미장에서 각각 **최대 3종목**을 스크리닝한다(적격 종목이 없으면 "현재 적격 종목 없음").
- 과거 모든 스크리닝 결과의 "추천 시점 직전 종가 → 현재" 수익률을 추적해 기법별 통계를 낸다.
- 모든 결과는 **"스크리닝 결과(통계용)"** 이며 투자 권유가 아니다.

## 2. 배경
- 사용자는 휴대폰 브라우저/GitHub 앱으로 필요할 때만 실행하고 결과를 확인하고자 한다.
- 최종 선정은 사용자 결정에 따라 **전부 LLM이 수행**한다. LLM은 수천 종목을 한 번에 볼 수 없으므로, LLM이 **숫자 기반 1차 필터 도구**를 호출해 후보를 줄인 뒤 최대 3종목과 사유를 고른다. 모든 숫자는 도구가 계산하고 LLM은 숫자를 만들지 않는다.
- 일관성은 **2단계 검수**(Claude 1차 → Gemini 2차)로 확보한다.

### 3.2 기법별 설정
- 유니버스 전역 기준은 미결(Q11). SEPA는 **기법 전용** 국장 기준(시가총액 ≥ 1조원·20일 평균 거래대금 ≥ 100억원 등, 사용자 설정)을 쓰며 다른 기법에는 적용하지 않는다. SEPA 미장 기준은 Q19.
- SEPA 판정 등급(원문): BUY CANDIDATE / WATCH / EXCLUDE. 개수 규칙(최대 3)은 BUY CANDIDATE에만 적용하며 WATCH로 채우지 않는다. 화면·저장 표기 문구는 Q24, WATCH 표시·추적은 Q23.

## 4. 사용자 시나리오
1. 사용자가 GitHub(웹/앱)에서 워크플로를 열고 "Run workflow"를 누른다. 기법을 체크박스로 고르고, 필요하면 범위를 하나 이상 체크한다(예: 코스피200 + 코스닥150, S&P 100). 범위를 안 고르면 기법별 기본 범위를 쓴다.
2. 워크플로가 데이터 수집 → Claude가 도구 호출로 1차 필터·판정(1차 검수) → Gemini가 같은 데이터로 2차 검수(승인·하향) → 하향 시 재검토 → 최종 결과 저장을 수행한다.
3. 사용자는 휴대폰 브라우저로 결과 화면을 열어, 기법별 국장·미장 최대 3종목(없으면 "현재 적격 종목 없음")과 LLM 사유를 본다.
4. 사용자는 이력 화면에서 과거 모든 스크리닝 결과의 현재까지 수익률과 기법별 통계를 본다.

## 5. 기능 요구사항
| ID | 요구사항 |
|---|---|
| F1 | 수동 실행: workflow_dispatch로만 실행되며, 입력은 기법별 체크박스(active 기법마다 1개)와 범위 체크박스(자주 쓰는 범위 10개, 여러 개 선택 가능 — 둘 다 레지스트리·설정에서 자동 생성), 추가 범위 ID 입력칸(나머지 범위), 시장, 모드, dry-run이다. |
| F2 | 플러그인: 각 기법은 독립 모듈이며, 공통 인터페이스(1차 필터 → LLM 판단 입력 생성 → 결과)를 따른다. 기법 추가 시 공통 코드 수정 없이 등록만으로 동작한다. |
| F3 | 1차 필터: 기법별 숫자 조건으로 시장별 후보군을 N개 이하로 줄인다(N은 미결 Q4). 통과 종목이 적어도 조건을 자동 완화하지 않으며, 0개면 LLM을 호출하지 않고 "현재 적격 종목 없음"으로 기록한다. |
| F4 | LLM 판단: LLM이 도구가 반환한 후보군 데이터로 시장별 **최대 3종목**(0~3)과 종목별 사유를 낸다. 기준 미달 종목으로 개수를 채우지 않는다. 사유의 숫자는 도구 반환값과 일치해야 한다. 제공자는 설정으로 교체 가능하다. |
| F5 | LLM 출력 검증: 후보군 밖 종목, 중복, 4개 이상 응답은 거부하고 재시도 또는 실패 처리한다. 0~3건 응답은 정상으로 처리한다. |
| F6 | 결과 저장: 실행 ID, 실행 시각, 기법, 시장, 종목코드/명, 기준가(추천 시점 직전 종가)와 그 날짜, 사유, LLM 제공자/모델명, 1차 필터 통과 종목 수를 저장한다. 결과가 0건인 기법·시장도 "현재 적격 종목 없음"과 1차 필터 통과 종목 수를 실행 이력에 남긴다. 과거 결과는 덮어쓰지 않고 누적한다. |
| F7 | 수익률 추적: 모든 과거 결과에 대해 (현재가 또는 최신 종가 ÷ 기준가 − 1)을 계산해 표시한다. 현재가 산출 시점을 함께 표시한다. (SEPA의 Entry 기준·WATCH 추적 여부는 Q22·Q23) |
| F8 | 기법별 통계: 기법·시장별 결과 수, 평균 수익률, 중앙값, 플러스 수익 비율(승률)을 표시한다. 0건 실행은 수익률 계산 대상이 아니다. |
| F9 | 표기: 결과/이력 화면 상단에 "스크리닝 결과(통계용) — 투자 권유 아님"을 표시한다. 매수/매도 등 권유 표현을 쓰지 않는다(SEPA 판정 원문 표기와의 충돌은 Q24). |
| F10 | 보안: API 키 등 비밀값은 GitHub Secrets/환경변수로만 읽는다. 저장소에 커밋하지 않는다. |
| F11 | 실패 처리: 데이터 소스 오류(예: 429), LLM 오류 시 해당 기법·시장을 "실패"로 기록하고 다른 기법·시장은 계속 진행한다. 잘못된 결과를 저장하지 않는다. "현재 적격 종목 없음"은 실패가 아니다. |
| F12 | 기법 전용 판정(SEPA 착수 시): 기법 명세가 판정 등급·코드 검증 규칙을 정의하면 기법 전용 필드로 저장하고, 코드 검증을 통과하지 못한 종목은 최상위 등급(SEPA: BUY CANDIDATE)으로 저장하지 않는다. |
| F13 | 2단계 검수: 같은 데이터 스냅샷으로 Claude가 먼저 판정(1차)하고, Gemini가 1차의 적격·관찰 종목만 검수(2차)해 종목마다 승인 또는 하향(관찰·제외)한다. 2차는 새 종목을 더하거나 판정을 올리지 않는다. 최종 적격 = 1차 적격 + 2차 승인. 하향된 종목은 1차가 근거를 보고 수용하거나 반론하고 2차가 다시 검수(최대 횟수 Q33), 끝까지 이견이면 낮은 쪽으로 확정. 1차·2차·최종 결과와 2차 승인율을 저장한다. 1차 또는 2차가 실패하면 그 기법·시장은 "실패"로 기록하고 최종 적격을 내지 않는다. 검수 순서(제공자)는 설정으로 바꿀 수 있다. |
| F14 | 비용 상한: 실행 1회 LLM 비용을 추적하고 상한(Q31)에 닿으면 새 호출을 멈춘다. 못 돌린 기법·시장은 "예산 초과로 미실행"으로 기록하고, 부분 결과를 완성 결과처럼 보이지 않게 한다. 실행마다 모델별·기법별 비용을 기록한다. |
| F15 | 범위(유니버스) 제한: 범위 프리셋을 둔다 — 국장: 전체·코스피 전체·코스닥 전체·코스피200·코스피100·코스피50·코스닥150·KRX300 / 미장: 전체·나스닥 전체·NYSE 전체·S&P 500·S&P 100·나스닥100·다우30·필라델피아 반도체·러셀2000. 거래소 전체 범위는 보통주만 쓰고, 무거운 데이터는 유동성 하한으로 먼저 줄인 뒤 조회한다. 기법마다 시장별 **기본 범위 목록**과 허용 범위를 설정한다. 실행 폼에서 범위를 여러 개 체크하면 체크된 기법 모두에 적용하고(허용 범위 밖은 그 기법에서 제외·기록, 남는 범위가 없으면 그 기법×시장은 "실패(범위)"), 시장별로 하나도 안 고르면 기본 범위(국장 전체·미장 전체)를 쓴다. 여러 범위는 합집합(중복 1번)에서 시장별 최대 3종목을 고른다(제안, Q37). 공식 구성종목을 못 받으면 ETF 보유 종목으로 근사하고 "근사"로 표시한다. 실행마다 범위별 ID·출처·근사 여부·기준일·종목 수를 기록하고, 결과 행에 범위 집합과 그 종목이 속한 범위를 저장해 범위별 통계를 낼 수 있게 한다. |
| F16 | 데이터 소스: 주식킹(stock-DASHBB)과 같은 네이버 증권 API를 국장·미장 1순위 소스로 쓰고(같은 요청 헤더·재시도·장 마감 확인), 실패 시 설정된 대체 소스(pykrx·DART·yfinance)로 넘어간다. 어느 소스 값인지 기록한다. 비공식 API이므로 응답 형식이 바뀌면 그 소스를 "실패"로 처리하고 빈 결과로 바꾸지 않는다. |

## 6. 합격 기준 (tester 검증용)
v0.1 번호 유지 — AC2·AC5·AC9·AC10·AC11 수정, AC15~AC24 신규.

- AC2: "전체"로 1회 실행하면, 성공한 기법·시장마다 0~3건의 결과 레코드가 생성되고, 0건이면 그 기법·시장의 실행 이력에 "현재 적격 종목 없음"이 기록된다.
- AC3: 모든 결과 레코드에 F6 필드가 비어 있지 않다(사유 포함).
- AC4: 기준가는 실행 시각 이전 마지막 거래일의 종가이며, 해당 날짜가 레코드에 저장된다. (예: 장중 실행 시 전 거래일 종가, 휴장일 실행 시 직전 거래일 종가)
- AC5: LLM이 후보군 밖 종목·중복·4개 이상을 반환하도록 모킹하면, 해당 응답은 저장되지 않고 재시도/실패로 기록된다.
- AC6: 동일 기법을 2회 실행하면 이력에 두 실행이 모두 남는다(첫 실행 결과가 덮어써지지 않음).
- AC7: 기준가 10,000원·현재가 11,000원인 레코드의 수익률이 +10.00%로 표시된다.
- AC8: 기법별 통계(결과 수·평균·중앙값·승률)가 저장된 레코드로 수동 계산한 값과 일치한다.
- AC9: 결과/이력 화면에 "스크리닝 결과(통계용)" 문구가 있고, 화면·저장 데이터에 "매수", "매도", "추천 매수" 등 권유 표현이 없다(LLM 사유 포함 — 프롬프트로 금지하고 검출 시 처리, 처리 방식은 미결 Q9; SEPA 판정 표기는 Q24).
- AC10: 새 더미 기법을 플러그인 디렉터리에 추가하고 동기화 스크립트를 실행하면, 공통 코드 수정 없이 실행 폼에 그 기법 체크박스가 생기고 결과에 나타난다. 레지스트리와 체크박스가 어긋나면 CI가 실패한다.
- AC11: 제공자 목록 설정값만 바꿔(코드 수정 없이) 실행 모델 구성이 바뀐다(Claude·Gemini 모킹 제공자로 검증, CI에서 유료 호출 없음).
- AC12: 저장소 전체에서 API 키·계좌번호 패턴이 검출되지 않는다(시크릿 스캔 통과).
- AC13: 한 시장 데이터 소스를 실패하도록 모킹하면, 그 시장은 "실패"로 기록되고 나머지 시장/기법 결과는 정상 저장된다.
- AC14: 휴대폰 폭(360px)에서 결과·이력 화면이 가로 스크롤 없이 읽힌다.
- AC15: LLM이 후보 중 2종목만 반환하도록 모킹하면 2건이 정상 저장되고, 그 기법·시장은 "실패"로 기록되지 않는다.
- AC16: 1차 필터 통과 종목이 0개인 입력으로 실행하면 LLM이 호출되지 않고, 결과·이력 화면에 그 기법·시장이 "현재 적격 종목 없음"으로 표시된다.
- AC17: 1차 필터 통과 종목이 1개인 입력으로 실행하면 결과는 1건 이하이고, 1차 필터 임계값은 설정값 그대로다(자동 완화 없음).
- AC18: 모킹 Claude 1차가 A·B·C를 적격으로 내고, 모킹 Gemini 2차가 A 승인·B 제외로 하향·C 관찰로 하향, 재검토에서 1차가 C는 수용·B는 반론하고 2차가 B 하향을 유지하면: 최종 적격은 A 1건, B 제외, C 관찰로 저장된다. 1차·2차·최종 결과와 승인율(1/3)이 저장되고, 2차가 1차에 없던 종목을 내도록 모킹하면 그 응답은 거부된다.
- AC19: 모킹 비용 상한을 첫 기법 실행 비용보다 작게 두면, 이후 기법·시장은 "예산 초과로 미실행"으로 기록되고 실행 비용 기록이 남는다.
- AC20: LLM 사유에 도구 반환값에 없는 숫자가 들어가도록 모킹하면 그 응답은 저장되지 않고 재시도/실패로 기록된다.
- AC21: 기법의 국장 범위를 코스피200(픽스처 구성종목)으로 두고 실행하면 모든 후보·결과가 그 구성종목 안에 있고, 결과 행에 범위 ID가, 실행 기록에 범위 출처·종목 수가 저장된다.
- AC22: 실행 폼에서 기법 2개 중 1개만 체크하면 그 기법만 실행된다. 범위를 체크하면 체크된 기법 모두에 적용되고, 기법의 허용 범위 밖 범위는 그 기법에서 빠지며, 남는 범위가 없으면 그 기법만 "실패(범위)"로 기록된다.
- AC23: 범위 2개(픽스처 코스피200 10종목 + 코스닥150 8종목, 겹침 2종목)를 체크하고 실행하면 후보는 합집합 16종목 안에서만 나오고(중복 1번), 결과는 시장별 최대 3건이며, 결과 행에 범위 집합(`kospi200+kosdaq150`)과 그 종목이 속한 범위가 저장된다.
- AC24: 범위의 공식 구성종목 소스가 실패하도록 모킹하면 ETF 보유 종목(주식만)으로 대체되고, 실행 기록과 결과 화면에 "근사"가 표시된다.

### 6.1 SEPA 착수 시 추가 합격 기준 (현재 검증 대상 아님)
- AC-S1: 국장에서 시가총액 4,000억원 종목, 또는 시가총액 2조원·20일 평균 거래대금 90억원 종목은 SEPA 1차 필터를 통과하지 못한다.
- AC-S2: Pivot 10,000 · 기준일 종가 10,600이면 Extension이 +6.00%로 계산된다.
- AC-S3: Entry 10,000 · Stop 9,500 · Target 10,900이면 R/R 1.80으로 계산되고 BUY CANDIDATE로 저장되지 않는다. Target 11,000이면 R/R 2.00으로 R/R 조건을 충족한다.
- AC-S4: LLM이 구조 레벨 목록에 없는 Stop을 반환하거나, 마지막 일봉 날짜가 기준일보다 이르면 그 종목은 BUY CANDIDATE로 저장되지 않는다.
- AC-S5: BUY CANDIDATE 조건을 충족하는 종목이 1개뿐인 모킹 입력이면 BUY CANDIDATE는 1건만 저장되고, 다른 종목의 WATCH 판정은 바뀌지 않는다.
